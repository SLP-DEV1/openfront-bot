# Schema-7 Campaign — Failure Analysis (plan.md §43)

Campaign: `campaign-schema7-overnight-20260925`
Engine: `13b403387af01d388f8c8ed8c953b6d3a11d1457` · Verdict: **Category C (NEGATIVE RESULT)**

This file records *what did not work, why, and the evidence*, distinct from the
narrative in `final-report.md`. Every number below is traceable to an artifact in
this folder.

## 1. The gate that failed

The §38 holdout gate requires, among other things, **Schema7 > Rule on Dev**
(D-24, the best trained schema-7 variant) on the new dev seeds. It was NOT met:

| seed | D-24 (schema-7) | rule-basis | winner |
|------|-----------------|------------|--------|
| aggro-train-001 | 55607 | 55607 | tie (byte-identical) |
| aggro-train-002 | 49169 | 76036 | rule (D-24 −26867) |

Source: `dev-comparison.json` (`schema7-D24` arm) and `turn-divergence.json`
(`finalLand`). Because the gate failed, the §38/§39 final holdout was correctly
**not** started (see `holdout-protocol.json` / `holdout-results.json`).

## 2. Per-variant failure mode

10 variants were trained (A–E × 24/40). Their dev behavior splits into two
groups (source: `candidate-comparison.json`, `dev-comparison.json`):

- **9 of 10 are byte-identical to rule-basis** on both dev seeds
  (`differentExecutedTurns = 0`, same land). Their argmax reproduces the rule's
  dispatch order, so the controller is active but never changes the emitted
  intent.
- **1 of 10 (D-24)** diverges (201 turns on seed 002) but ends *worse* on the
  divergent seed.

Consequence: the only variant that actually exercises the controller fails the
dev comparison; the other nine never diverge enough to matter. Neither outcome
yields a promotion-eligible candidate.

## 3. Root cause (reproducible)

The training signal rewards **imitating the rule's branch**, not improving the
outcome.

- The on-policy branch dataset (`dataset.json`, 41865 frames / 132 matches,
  SHA in `dataset-manifest.json`) labels each decision frame by the **rule's
  dispatch order**. There is no counterfactual "what would have been *better*"
  label.
- With that target, a rank-loss objective converges to the rule: 9/10 variants
  become byte-identical to rule. This is the expected optimum of the objective,
  not a bug in the controller.
- The one variant pushed away from the rule (D-24, highest hard-negative boost)
  diverges on dispatch *order* without improving the outcome — on seed 002 it
  lands 26867 below rule.

Evidence of the imitation signal (source: `models/D-24/evaluation.json`):
`flipToLowerRate = 0.1528`, `flipToHigherRate = 0` over 11928 flip frames — when
the model deviates it drifts toward the rule's *lower*-ranked branch, i.e. it
has no learned signal that a higher-ranked branch is better.

## 4. What was NOT a failure (mechanism is sound)

The controller plumbing is proven correct, so the negative result is about the
*trained policy*, not the architecture:

- The synthetic `navaltest` model (hand-crafted boat/warship preference) drives
  164 divergent turns and **beats** rule on seed 001 (58537 > 55607)
  (`dev-comparison.json` note). The same mechanism, given a genuinely better
  preference, improves the outcome.
- §26 pre-gate and §27/§28 causality all PASS for D-24 (201 model-caused,
  legal, non-cosmetic, engine-confirmed divergent turns; `branch-funnel.json`,
  `engine-prescreen.json`).

## 5. Reproducibility

- Deterministic runs are reproducible from `models/{A..E}-{24,40}` +
  `models/navaltest` + pinned engine `13b40338…` + the dev-comparison settings
  (`World / Compact / Medium, FFA, 40 bots, autonomous, balanced, 9000-tick`).
- Raw `benchmark-results/pgate-*` dirs are kept locally (not committed) and are
  regenerated by re-running the engine with the same model + seed.
- Policy SHA256 for D-24: `e5dc6b175761dcd0eb74f7992d639edba34680db303bc526adb992ba40f17b14`
  (`dev-comparison.json`, `promotion-decision.json`).

## 6. Next bottleneck (the thing to fix next)

**Training signal / model quality**, not the controller:

1. Label branches by **outcome improvement**, not rule identity — e.g. a
   counterfactual land delta measured by re-running with each candidate branch
   instead of the emitted one (the §27 harness already measures held-land
   deltas; it can supply the label).
2. Break the 9/10 collapse: the objective must make "differ from rule" *cost*
   something only when it does not improve the counterfactual outcome.
3. Add a dev-seed diversity check (see §6 below) before re-running the gate.

## 7. Open items / limitations carried in the verdict

- **§36 mode gates:** the live dev evaluation ran the FFA seed pair only. 1v1,
  official-2v2, and ffa-duo are all present in the **training dataset**
  (`dataset-manifest.json`, `s20ModeDiversity`), but were not separately gated in
  dev. Recorded as PARTIAL in `dev-evaluation.json` (`s36_modeGates`).
- **§37 decisive outcomes:** only 2 decisive paired outcomes exist
  (D-24/002 negative; navaltest/001 positive-synthetic) vs the ≥5 required.
  Recorded in `dev-evaluation.json` (`s37_decisiveOutcomes`). Both consistent
  with Category C; no gate was manipulated (`promotion-decision.json`, §40).

These limitations are why the verdict is C (not A) and are explicitly listed here
rather than hidden.
